# Contributing

Keep domain code independent of frameworks and vendors. Add tests with behavior changes. Prefer additive, versioned contracts. Keep source assets immutable and make edits through new revisions. Explain AI proposals with rationale, evidence, confidence, and strategy version. Never describe feedback capture as autonomous model training.

Use branches such as feature/slice, fix/issue, or docs/topic. Use imperative commit subjects, for example: feat(domain): add render job contract. Before a pull request, run repository checks and describe what is implemented, deferred, and assumed.
