# Guided creation

New video opens a purpose chooser before creating a project or asking for uploads:

* **Edit my footage** keeps the spoken-video Director/highlights/editor flow.
* **Tell a story** accepts multiple videos and photos and builds an editable storyboard.
* **Create from an idea or script** can plan without uploads. Every suggested visual must be resolved to a project asset before assembly.

Story drafts contain the brief, target duration, format, selected asset IDs, scene order/ranges/text, script, chosen narration and audio/text options. They survive reload in versioned local storage, scoped to the project. Drafts are local to the browser until assembled; uploaded assets and saved timeline revisions are stored on the server. No signed media links are persisted in the draft.

## Media and narration

The creator can assign uploaded photos/videos, import an exact stock item, or generate an image for a selected scene. Generated bytes are validated as a decodable PNG, stored once as a normal project asset, and reused in preview/export. Generation never substitutes a different visual at export time.

AI storyboard planning combines existing transcripts with labelled visual samples. It samples a photo once and a video at its start and midpoint, from at most the first 12 selected assets, 50 MiB per asset and 100 MiB total, within a 15-second sampling deadline. Sampling downloads can be cancelled; each FFmpeg sample also has a ten-second limit. Unknown-size, oversized and unsampled items rely on filenames/transcripts. The plan states how many media items were visually sampled. Sampling is not a claim to have watched every second. A provider failure is marked as a built-in storyboard in selected media order. The provider request has a separate 60-second deadline.

Record narration, upload human narration, or synthesize an AI voice from the editable script. Preview narration before assembling. With a narration track, source speech is muted. The complete narration determines the minimum timeline length; a final photo extends in one input, or a final video repeats within its source bounds. Assembly refuses more than 40 resulting picture clips rather than creating an unbounded render graph. Without narration, original video sound remains. Optional speech captions are transcribed from the actual narration, not estimated from script word counts. Optional scene text and generated music are separate controls.

Still images are primary timeline clips, not video URLs passed to a video element. The browser advances photos on a clock and switches between photos and videos; FFmpeg loops each photo for its actual scene duration. Scene text can bind to a specific clip occurrence, including repeated uses of the same photo. Whole-story narration remains at timeline zero when scenes are reordered.

## Configuration

Existing `OPENAI_API_KEY` and `DIRECTOR_MODEL` configure AI storyboards and typed narration. Existing Pexels/Pixabay/GIPHY keys configure stock availability. The upload endpoint allows 40 uploads per minute; the browser sends files sequentially and retains successful uploads when another file fails.

Set `IMAGE_MODEL` to an image model available to the server's OpenAI account to enable image generation. It is deliberately unset by default, and capabilities report image generation as unavailable until both model and key are configured. The adapter uses `/images/generations`, one 1024-square PNG, a 90-second deadline, project authorization, and a three-per-minute route limit. Model access and billing must be verified against the actual deployment. The UI does not offer generated video, which has no configured provider yet. Stock video is supported.

## Bounds and recovery

The server validates ownership, media kind, finite source ranges, video duration, photo start zero, 1–40 scenes, 0.5–60 seconds per scene, total story duration up to ten minutes, and known narration duration. Stale revision assembly is rejected; earlier revisions remain available through undo/history. Concurrent editor transaction guarantees retain the existing persistence implementation and have not been expanded here.

Mixed-media stories cannot be sent to the existing single-video cut planner, which would replace the timeline from one source. The editor links back to Storyboard instead. Mixed-media checks explicitly report built-in timing/text checks, without claiming an AI visual review or treating intended stills as frozen-video defects.

## Release gates

Local tests exercise actual mixed-media FFmpeg output and full narration duration, repeated-photo text anchors, ownership/range/revision validation, provider fallback, and exact generated-image storage. Browser tests cover the chooser, uploads, draft recovery, ordering, photo/video playback, stock/generated visual assignment and human narration/caption requests in Chromium and mobile WebKit.

Before release, run those browser tests in CI, deploy the exact passing revision, test authenticated provider calls and full exports, and test physical iPhone Safari/Android Chrome. The outstanding Freedom playback/export incident remains a separate release blocker. Generated video, exhaustive inspection of every frame in every upload, cross-device unassembled drafts, and a mixed-media AI picture review are not implemented by this change.

## Idea-mode narration default

Create from an idea defaults to AI narration, with an explicit preference beside the brief. Review or edit the script, select the voice and delivery, and optionally preview the audio. Assemble generates the narration automatically before captions and timeline saving. Generation failure stops assembly rather than silently producing a music-only export. An unchanged prepared recording is reused across assembly failures and reloads; changing script, voice, or delivery generates a new recording. Human narration and an explicit no-narration choice remain available and persist in the draft. Existing saved recordings are preserved during draft migration.
